# Cycle 002 - Loop Safety Hardening

## Signal

The user asked to add stronger loop skills and prevent virus-like behavior while
continuing to improve NotchMove through Agent teams.

Agent teams reviewed product loop scope, Swift/macOS verification, and macOS
security hardening. The highest-confidence shared finding was that loops should
first become better at rejecting unsafe release guidance and source drift before
adding broader product surfaces.

## Scope Gate

Kept in scope:

- release/distribution safety
- source-level entitlement and privacy-string drift
- localization key and placeholder parity
- loop verification quality

Kept out of scope:

- accounts, cloud sync, analytics, payments, or dashboard expansion
- broad AI, Voice Input, schedule, or Notch Hub growth without a concrete
  reminder-first blocker
- replacing signed manual smoke testing with incomplete automation

## Result

Cycle 002 adds deterministic loop checks:

- `script/check_localization_keys.py`
- `script/check_source_privacy.sh`
- expanded `script/verify_release_privacy.sh`
- updated `script/loop_verify.sh`

It also removes distribution guidance that told testers to bypass Gatekeeper
quarantine and replaces it with safer re-download guidance.

Runtime hardening:

- Custom OpenAI-compatible provider Base URLs now require HTTPS for remote
  hosts, with HTTP allowed only for loopback local development.
- AI provider tests cover both cleartext remote rejection and loopback allowance.
